## Chapter 4: Ingestion Foundations: Dataflows Gen2, Pipelines & OneLake Shortcuts — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Dataflow Gen2 vs Data pipeline Copy activity — when to use each? | Dataflow Gen2: low-code Power Query transformations (joins, merges, unpivot, cleansing). Pipeline Copy activity: bulk data movement with no/minimal transformation. Exam tip: if the requirement mentions 'transform' or 'reshape', pick Dataflow Gen2; if it says 'move' or 'orchestrate', pick a pipeline. |
| 2 | Dataflow Gen2 vs Notebook — when to use each? | Dataflow Gen2: citizen-developer, GUI-based transforms, moderate data volumes. Notebook (PySpark): code-first, custom libraries, full control over partitioning/parallelism, best for large-scale/complex engineering. Exam tip: 'no-code/low-code analyst' → Dataflow Gen2; 'custom Python/ML/Spark control' → Notebook. |
| 3 | What is a OneLake shortcut? | A virtual reference within OneLake to data stored elsewhere (another Fabric item or external storage) — no data is copied or duplicated. Exam tip: shortcuts appear as native folders/tables but physically remain at the source. |
| 4 | Internal vs external OneLake shortcut — key difference? | Internal: points to another location inside OneLake (e.g., a different workspace's Lakehouse/Warehouse). External: points outside Fabric entirely (ADLS Gen2, Amazon S3, S3-compatible, Google Cloud Storage, Dataverse). Neither copies data. |
| 5 | External OneLake shortcut supported source types? | Azure Data Lake Storage Gen2, Amazon S3, S3-compatible storage, Google Cloud Storage, Dataverse. Exam tip: know these are 'reference' connections, not copy-based ingestion. |
| 6 | Incremental refresh in Dataflow Gen2 — required parameters? | RangeStart and RangeEnd parameters of type Date/DateTime, bound to a filter step on the source query. Exam tip: without query folding support at the source, incremental refresh benefits are limited. |
| 7 | Where does Dataflow Gen2 stage data by default? | Data is staged into an internal Fabric storage location (backed by a Lakehouse) before loading to the destination, consuming Fabric Capacity Units (CUs). Exam tip: staging can be disabled per query for simple pass-through scenarios. |
| 8 | Fabric Data pipeline trigger types? | Schedule trigger (recurring, time-based) and On-demand/manual run. Pipelines can also be chained using the Invoke Pipeline activity. Exam tip: 'run every day at X time' = Schedule trigger, not a manual action. |
| 9 | What does Fast Copy do in Dataflow Gen2? | Fast Copy accelerates large-scale data movement within a Dataflow Gen2 by bypassing row-by-row Power Query processing for bulk transfers, improving performance for big source datasets. |
| 10 | Does a OneLake shortcut consume additional storage? | No — shortcuts are virtual references; the data stays at its original location. Only compute/read costs apply when querying through the shortcut, not duplicate storage costs. |
| 11 | Which typically consumes more Capacity Units: a simple Copy activity or an equivalent Dataflow Gen2 load? | Dataflow Gen2 generally consumes more CUs than a plain Copy activity for the same data volume, because of the Power Query transformation engine and staging overhead. Exam tip: for simple 'move data as-is' scenarios, prefer Copy activity to conserve capacity. |
| 12 | When should you choose a Data pipeline over Dataflow Gen2? | Choose a pipeline when the requirement is orchestration — sequencing activities, conditional branching, calling stored procedures, or invoking other pipelines/notebooks — rather than performing the transformation logic itself. |
